# 项目指导文件规范（AGENTS / CLAUDE）

AGENTS 是简短阅读路由和必要规则，不能复制 README、TODO、架构、完整测试流程或技能正文。CLAUDE 是同目录 `AGENTS.md` 的相对软链，不维护第二份文字；创建前处理现有有效独有规则，已有正确软链无需操作。

只读本次范围内生效的父级与局部指导、相关权威来源以及受影响入口，不因改一条规则扫描所有代码或所有子目录规则。保留真实项目事实、安全边界、团队规范和仍适用的用户偏好，不因具体或属于个人要求而删除；缺少证据不宣称旧要求已过时。目录级规则只有真正独立约束时才创建。

交付前检查本次改动的规则是否可定位、引用是否存在、软链是否指向正确 AGENTS 且无循环。不因此安排其他客户端运行验证，不修改用户全局配置，不额外产规则审计报告。

## 写什么

- 开始或继续项目任务时的活动入口；只读当前任务所需材料。
- 按改动类型路由到权威文档，说明触发条件。
- 真实且持续有效的项目边界，例如不可编辑的生成物、必须保留的数据契约、特定改动的必要验证。
- 已授权工作的执行范围与真正需要审批的不可逆操作；普通读取、可逆修改不反复请示。

技能不自动安装项目规则，不把当前会话要求悄悄写成全局偏好。目录作用域与继承按当前工具的实际行为核对，不照搬其他平台规则。项目入口可以说明普通开发维护 TODO；专项技能仍由用户显式调用，不能在 AGENTS 中要求每个任务加载它们。

## README 维护边界

用户要求创建或实质重写项目 AGENTS 时，必须写入下方示例中的两条 README 维护规则，包含修改边界与主动建议，不只提供阅读路由。整理已有 AGENTS 时，保留等效规则；本次涉及 README 维护约定且规则缺失或过宽时补齐。用户另有明确要求时以其要求为准；局部规则沿用上层约定，不重复写入。

按项目实际语言和路径替换示例中的“双语 README”；单语项目只约束现有 README，不因此创建翻译。事实修正可以替换已有说明中的版本号、命令或行为描述，但不能借此移除说明项、段落或章节。已明确授权的新增或删除直接按授权范围执行；笼统的“同步文档”“整理 README”不视为新增或删除授权。

## 精简时的判断

逐条看必要性，不按篇幅或“具体”本身删规则：

- 冗长宽泛的技能触发说明改为准确路由，不复制 description。
- 多种长流程分离为按需引用；与本任务无关的内容不提前读。
- 取消无条件长步骤脚本，保留确有顺序依赖的流程。
- 不要求每次小改前通读全仓库或大量文档；已读且未变的材料不重复读。
- 保留与改动相关的真实项目验证门槛；仅为了督促模型而重复核查的要求才删除。无依据不判测试过时。
- 将宽泛“必须先询问”改为明确权限边界，已获授权不再次批准。

## 最小示例

```markdown
# AGENTS.md

继续项目任务前读取 TODO.md 的当前里程碑和相关条目；完成默认勾选，必要验证最多一条短句，不追加工作日志。

## 按改动类型阅读

| 改动 | 先读 |
| --- | --- |
| 公共用法或安装入口 | README.md 及对应正式翻译 |
| 模块边界或关键流程 | docs/tech/architecture.md 中相关部分 |
| 任务顺序和完成条件 | TODO.md；涉及未来安排时再读 docs/roadmap.md |

## 项目边界

- 修改公开内容导致与 README 已有内容产生冲突时，仅同步修正双语 README 中受影响的已有内容，使其与公共事实对齐；无冲突不顺带修改。未经用户明确授权，不新增内容；删除任何 README 现有内容前须征得用户同意。
- 本次改动产生值得补充或调整的 README 内容时，主动沿用现有章节、格式和语气提出具体修改草案，说明位置与理由，并询问是否同步更新双语 README；确认前不写入，不仅等待用户提出要求。
- 按需补充本项目已核实、不能从入口发现的其他必要约束；没有则省略本条。
```

表中路径仅为示例，输出时改为存在的文件和有效链接。规则可以紧凑，但必须说明何时生效、做什么，不用“收敛治理闭环”等含混术语代替动作。
